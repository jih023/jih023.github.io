# Chapter 3. 람다 표현식

## 3.1 람다란 무엇인가?

### 람다 표현식

- 메서드로 전달할 수 있는 익명 함수를 단순화한 것
- 이름은 없지만, 파라미터 리스트, 바디, 반환 형식, 발생할 수 있는 예외 리스트는 가질 수 있음

### 람다의 특징

- 익명
- 함수
  - 메서드처럼 특정 클래스에 종속되지 않으므로 함수라고 부름
- 전달
  - 람다 표현식을 메서드 인수로 전달하거나 변수로 저장 가능
- 간결성

### 람다 코드 예시

- 기존 코드

  ```
  Comparator<Apple> byWeight = new Comparator<Apple>() {
      public int compare(Apple a1, Apple a2) {
          return a1.getWeight().compareTo(a2.getWeight());
      }
  }
  ```
- 람다를 이용한 코드

  ```
  Comparator<Apple> byWeight =
      (Apple a1, Apple a2) -> a1.getWeight().compareTo(a2.getWeight());
  ```

  - 위 코드처럼 람다 표현식은 파라미터, 화살표, 바디로 이루어짐
    - (Apple a1, Apple a2) -&gt; a1.getWeight().compareTo(a2.getWeight());
- 자바 8의 유효한 람다 표현식
  - (String s) -&gt; s.length()
    - String 형식의 파라미터 하나
    - int 반환
  - (Apple a) -&gt; a.getWeight() &gt; 150
    - Apple 형식의 파라미터 하나
    - boolean 반환
  - (int x, int y) -&gt; { System.out.println("Result:"); System.out.println(x + y); }
    - int 형식의 파라미터 두 개
    - void 리턴
  - () -&gt; 42
    - 파라미터 없음
    - int 42 반환
  - (Apple a1, Apple a2) -&gt; a1.getWeight().compareTo(a2.getWeight())
    - Apple 형식의 파라미터 두 개
    - int 반환 (두 사과의 무게 비교 결과)

### 표현식 스타일 람다

- 아래 형식 둘 다 가능
  - (parameters) -&gt; expression
  - (parameters) -&gt; {statements;}
- 예시
  - () -&gt; {}
  - () -&gt; "Raoul"
  - () -&gt; {return "Mario";}
  - (Integer i) -&gt; return "Alan" + i;
    - ⇒ X
    - (Integer i) -&gt; { return "Alan" + i; } 이 맞음
  - (String s) -&gt; {"Iron Man";}
    - ⇒ X
    - (String s) -&gt; "Iron Man" 이 맞음

## 3.2 어디에, 어떻게 람다를 사용할까?

### 함수형 인터페이스

- 추상 메서드가 정확히 하나인 인터페이스
- default/static 메서드는 여러 개 있을 수 있음
- @FunctionalInterface 으로 함수형 인터페이스의 조건에 맞는지 검사해줌

  ```java
  @FunctionalInterface
  interface CustomInterface<T> {
      // 추상 메서드 1개
      T myCall();

      default void printDefault() {
          System.out.println("Hello Default");
      }

      static void printStatic() {
          System.out.println("Hello Static");
      }
  }
  ```
- 람다 표현식으로 함수형 인터페이스의 추상 메서드 구현을 직접 전달할 수 있으므로 전체 표현식을 함수형 인터페이스의 인스턴스로 취급할 수 있음

  ```
  Runnable r1 = () -> System.out.println("Hello World 1");

  Runnable r2 = new Runnable() {
      public void run() {
          System.out.println("Hello World 2");
      }
  };

  public static void process(Runnable r) {
      r.run();
  }
  process(r1); // Hello World 1
  process(r2); // Hello World 2
  process(() -> System.out.println("Hello World 3")); // Hello World 3
  ```

### 함수 디스크립터

- 람다 표현식의 시그니처를 서술하는 메서드
  - Runnable 인터페이스의 유일한 추상 메서드 run은 인수와 반환값이 없으므로
  - Runnable 인터페이스는 인수와 반환값이 없는 시그니처
  - () -&gt; void

인터페이스추상 메서드함수 디스크립터

|  |  |  |
| --- | --- | --- |
| Predicate&lt;T&gt; | boolean test(T t) | (T) → boolean |
| Consumer&lt;T&gt; | void accept(T t) | (T) → void |
| Function&lt;T, R&gt; | R apply(T t) | (T) → R |
| Supplier&lt;T&gt; | T get() | () → T |
| Comparator&lt;T&gt; | int compare(T, T) | (T, T) → int |
| BiFunction&lt;T, U, R&gt; | R apply(T, U) | (T, U) → R |

## 3.3 람다 활용 : 실행 어라운드 패턴

- 자원 처리에 사용하는 순환 패턴
  1. 자원 열기
  2. 자원 처리
  3. 자원 닫기
- 실행 어라운드 패턴

  ```
  public String processFile() throws IOException {
      try (BufferedReader br =
              new BufferedReader(new FileReader("data.txt"))) {
          return br.readLine(); // 자원 처리 작업
      }
  }
  ```

  - 중복되는 준비 코드와 정리 코드가 실제 자원 처리 작업을 감싸고 있음

### 3.3.1 1단계 : 동작 파라미터화를 기억하라

- 기존의 설정, 정리 과정은 재사용하고 processFile 메서드만 다른 동작을 수행하도록 하려면
  - processFile 동작 파라미터화하기
- processFile 메서드가 한 번에 두 행 읽게 하기

  ```
  String result = processFile(
      (BufferedReader br) -> br.readLine() + br.readLine());
  ```

### 3.3.2 2단계 : 함수형 인터페이스를 이용해서 동작 전달

- BufferedReader → String 과 IOException을 던질 수 있는 시그니처와 일치하는 함수형 인터페이스

  ```java
  @FunctionalInterface
  public interface BufferedReaderProcessor {
      String process(BufferedReader b) throws IOException;
  }

  public String processFile(BufferedReaderProcessor p) throws IOException {
      ...
  }
  ```

### 3.3.3 3단계 : 동작 실행

- 위에서 만든 인터페이스에 정의된 process 메서드의 시그니처(BufferedReader → String)와 일치하는 람다를 전달할 수 있다
- processFile 바디 내에서 BufferedReader 객체의 process를 호출할 수 있다
  - 람다 표현식으로 함수형 인터페이스의 추상 메서드 구현을 직접 전달할 수 있으므로

```
public String processFile(BufferedReaderProcessor p) throws
        IOException {
    try (BufferedReader br =
            new BufferedReader(new FileReader("data.txt"))) {
        return p.process(br);
    }
}
```

### 3.3.4 4단계 : 람다 전달

- 이제 람다를 이용해 다양한 동작(자원 처리 동작)을 processFile 메서드로 전달할 수 있다

```
// 한 행을 처리하는 코드
String oneLine = processFile((BufferedReader br) -> br.readLine());

// 두 행을 처리하는 코드
String twoLines = processFile((BufferedReader br) -> br.readLine() + br.readLine());
```

## 3.4 함수형 인터페이스 사용

#### 함수 디스크립터

- 함수형 인터페이스의 추상 메서드 시그니처
- 쉽게 말해, 람다를 넣을 자리의 "모양"
  - (파라미터 타입들) → 반환 타입

### 3.4.1 Predicate

- Predicate&lt;T&gt; 인터페이스의 추상 메서드 : boolean test(T t)
- T 형식의 객체를 사용하는 불리언 표현식이 필요한 상황에서 Predicate 인터페이스 사용 가능

  ```
  @FunctionalInterface
  public interface Predicate<T> {
      boolean test(T t);
  }
  public <T> List<T> filter(List<T> list, Predicate<T> p) {
      List<T> results = new ArrayList<>();
      for(T t: list) {
          if(p.test(t)) {
              results.add(t);
          }
      }
      return results;
  }
  Predicate<String> nonEmptyStringPredicate = (String s) -> !s.isEmpty();
  List<String> nonEmpty = filter(listOfStrings, nonEmptyStringPredicate);
  ```

### 3.4.2 Consumer

- Consumer&lt;T&gt; 인터페이스의 추상 메서드 : void accept(T t)
- T 형식의 객체를 인수로 받아서 어떤 동작을 수행하고 싶을 때 Consumer 인터페이스 사용 가능

  ```
  @FunctionalInterface
  public interface Consumer<T> {
      void accept(T t);
  }
  public <T> void forEach(List<T> list, Consumer<T> c) {
      for(T t: list) {
          c.accept(t);
      }
  }
  forEach(
      Arrays.asList(1, 2, 3, 4, 5),
      (Integer i) -> System.out.println(i) // Consumer의 accept 메서드를 구현하는 람다
  }
  ```

### 3.4.3 Function

- Function&lt;T, R&gt; 인터페이스의 추상 메서드 : R apply(T t)
- 입력을 출력으로 매핑하는 람다를 정의할 때 Function 인터페이스 사용 가능
  - Ex) 사과의 무게 정보 추출, 문자열을 길이와 매핑

  ```
  @FunctionalInterface
  public interface Function<T, R> {
      R apply(T t);
  }
  public <T, R> List<R> map(List<T> list, Function<T, R> f) {
      List<R> result = new ArrayList<>();
      for(T t: list) {
          result.add(f.apply(t));
      }
      return result;
  }

  // [7, 2, 6]
  List<Integer> l = map(
      Arrays.asList("lambdas", "in", "action"),
      (String s) -> s.length() // Function의 apply 메서드를 구현하는 람다
  );
  ```

#### 기본형 특화 함수형 인터페이스

- 자바의 모든 형식은 참조형(Byte, Integer, Object, List), 기본형(int, double, byte, char)에 해당함
- 제네릭 파라미터(Consumer&lt;T&gt;의 T)에는 참조형만 사용 가능
- 이를 위해 자바에서 제공하는 기능
  - 박싱
    - 기본형 → 참조형
  - 언박싱
    - 참조형 → 기본형
  - 오토박싱
    - 편리하게 코드를 구현할 수 있도록 박싱과 언박싱이 자동으로 이루어짐
- int가 Integer로 박싱되는 예시

  ```
  List<Integer> list = new ArrayList<>();
  for (int i = 300; i < 400; i++) {
      list.add(i);
  }
  ```

  - 이런 변환 과정은 비용이 소모됨
- 기본형 특화 인터페이스
  - DoublePredicate, IntConsumer, LongBinaryOperator, IntFunction
  - ToIntFunction&lt;T&gt;, IntToDoubleFunction

  ```
  public interface IntPredicate {
      boolean test(int t);
  }

  IntPredicate evenNumbers = (int i) -> i % 2 == 0;
  evenNumbers.test(1000);  // 박싱 없음

  Predicate<Integer> oddNumbers = (Integer i) -> i % 2 != 0;
  oddNumbers.test(1000);  // 박싱
  ```

  - 두 번째 코드에서 일어나는 일

    ```sql
    호출부:  int 1000 ──박싱──▶ Integer 객체        (인자 타입이 Integer라서)
                                  ↓
    람다 안:  Integer ──언박싱──▶ int ──▶ % 2 ──▶ 비교 ──▶ boolean
                                                              ↓
    반환:                                            boolean 그대로 (박싱 없음)
    ```

## 3.5 형식 검사, 형식 추론, 제약

### 3.5.1 형식 검사

- 아래 람다 표현식을 사용할 때 컴파일러의 형식 확인 과정

  ```
  List<Apple> heavierThan150g =
      filter(inventory, (Apple apple) -> apple.getWeight() > 150);
  ```

  1. filter 메서드 선언 확인
     - filter(List&lt;Apple&gt; inventory, Predicate&lt;Apple&gt; p)
  2. filter 메서드는 두 번째 파라미터로 Predicate&lt;Apple&gt; 형식을 기대함
  3. Predicate&lt;Apple&gt;은 test라는 한 개의 추상 메서드를 정의하는 인터페이스임
     - boolean test(Apple apple)
  4. test 메서드는 Apple을 받아 boolean을 반환하는 함수 디스크립터를 묘사함
     - Apple → boolean
  5. filter 메서드로 전달된 인수는 이와 같은 요구사항을 만족해야 함
     - 함수 디스크립터는 Apple → boolean 이므로 람다의 시그니처와 일치함
     - 형식 검사가 성공적으로 완료됨

### 3.5.2 같은 람다, 다른 함수형 인터페이스

- 같은 람다가 다른 함수형 인터페이스와 호환될 수 있음
- Callable과 PrivilegedAction 인터페이스는 인수를 받지 않고 T를 반환하므로 아래 두 할당문은 모두 유효함

  ```
  Callable<Integer> c = () -> 42;
  PrivilegedAction<Integer> p = () -> 42;
  ```
- 또 다른 예시

  ```
  Comparator<Apple> c1 =
      (Apple a1, Apple a2) -> a1.getWeight().compareTo(a2.getWeight());
  ToIntFunction<Apple, Apple> c2 =
      (Apple a1, Apple a2) -> a1.getWeight().compareTo(a2.getweight());
  BiFunction<Apple, Apple, Integer> c3 =
      (Apple a1, Apple a2) -> a1.getWeight().compareTo(a2.getWeight());
  ```

### 3.5.3 형식 추론

- 컴파일러는 람다 파라미터 형식을 추론함

  ```
  // apple 형식 추론
  List<Apple> greenApples =
      filter(inventory, apple -> GREEN.equals(apple.getColor()));
  ```

  ```
  Comparator<Apple> c =
      (Apple a1, Apple a2) -> a1.getWeight().compareTo(a2.getWeight());
  Comparator<Apple> c =
      (a1, a2) -> a1.getWeight().compareTo(a2.getWeight()); // a1, a2 형식 추론
  ```

### 3.5.4 지역 변수 사용

- 람다 캡처링
  - 람다 표현식에서 외부에서 정의된 변수(자유 변수)를 사용하는 것

  ```
  int portNumber = 1337;
  Runnable r = () -> System.out.println(portNumber);
  ```

  - 캡처한 자유 변수는 final이거나 effectively final 이어야 함

  ```
  int portNumber = 1337;
  Runnable r = () -> System.out.println(portNumber);
  portNumber = 31337; // 컴파일 에러
  ```

## 3.6 메서드 참조

```
// 기존 코드
inventory.sort((Apple a1, Apple a2) ->
        a1.getWeight().compareTo(a2.getWeight()));

// 메서드 참조와 java.util.Comparator.comparing을 활용한 코드
inventory.sort(comparing(Apple::getWeight));
```

### 3.6.1 요약

- 메서드 참조의 장점
  - 명시적으로 메서드명을 참조함으로써 가독성을 높일 수 있음
- 메서드 참조 활용
  - 메서드명 앞에 구분자(::)를 붙임

#### 메서드 참조를 만드는 방법

1. 정적 메서드 참조
   - Integer::parseInt
2. 다양한 형식의 인스턴스 메서드 참조
   - String::length
   - (String s) -&gt; s.toUpperCase() 를 String::toUpperCase
3. 기존 객체의 인스턴스 메서드 참조
   - () -&gt; expensiveTransaction.getValue() 을 expensiveTransaction::getValue

inventory.sort(new Comparator<Apple>() {

```

inventory.sort((a1, a2) -> a1.getWeight().compareTo(a2.getWeight()));
```

- comparing 메서드 사용

Comparator<Apple> c = Comparator.comparing((Apple a) -> a.getWeight());

## 3.8 람다 표현식을 조합할 수 있는 유용한 메서드

### 3.8.1 Comparator 조합

```
Comparator<Apple> c = Comparator.comparing(Apple::getWeight);
```

#### 역정렬

- reversed 디폴트 메서드 사용

```css
inventory.sort(comparing(Apple::getWeight).reversed());
```

#### Comparator 연결

- 무게가 같은 두 사과가 존재하는 경우, 비교 결과를 더 다듬을 수 있는 두 번째 Comparator 만들어 사용
- thenComparing 메서드로 두 번째 비교자를 만듦

```css
inventory.sort(comparing(Apple::getWeight)
         .reversed()
         .thenComparing(Apple::getCountry));
```

### 3.8.2 Predicate 조합

- Predicate 인터페이스는 negate, and, or 메서드를 제공함
- 빨간색이 아닌 사과

  ```
  Predicate<Apple> notRedApple = redApple.negate();
  ```
- 빨간색이면서 무거운 사과

  ```
  Predicate<Apple> redAndHeavyApple =
      redApple.and(apple -> apple.getWeight() > 150);
  ```
- 빨간색이면서 무거운 사과 또는 그냥 녹색 사과

  ```
  Predicate<Apple> redAndHeavyAppleOrGreen =
      redApple.and(apple -> apple.getWeight() > 150)
              .or(apple -> GREEN.equals(a.getColor()));
  ```

### 3.8.3 Function 조합

```
Function<Integer, Integer> f = x -> x + 1;
Function<Integer, Integer> g = x -> x * 2;

Function<Integer, Integer> h1 = f.andThen(g); // g(f(x))
System.out.println(h1.apply(1)); // 4

Function<Integer, Integer> h2 = f.compose(g); // f(g(x))
System.out.println(h2.apply(1)); // 3
```
