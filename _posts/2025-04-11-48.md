### <strong>What is an Operating System?</strong>

운영체제 -&gt; 사용자와 하드웨어 사이의 인터페이스

제공하는 서비스

- 프로세스
- CPU 스케줄링
- 메모리 관리
- 파일 시스템
- 네트워킹

개발 목표 - machine을 더 편리하고 효율적으로 사용할 수 있도록 하는 것. (소프트웨어 엔지니어링 문제)

### <strong>Why study Operating System?</strong>

1. Abstraction (추상화)
   - 사용자에게 무한한 자원(CPU 시간, 메모리, 파일 공간)에 대한 환상을 어떻게 제공하는지?
2. System Design (시스템 설계)
   - 이 추상화들의 성능과 편리성
   - OS의 성능과 단순성
   - 하트웨어 / 소프트웨어의 기능
3. Primaty intersection point (주요 교차점)
   - 하드웨어, 소프트웨어, 프로그래밍 언어, 데이터 구조 및 알고리즘이 모두 합쳐지는 지점
4. Curiosity
   - 겉보기만이 아니라 내부 구조나 작동 원리를 깊이 들여다봐라!
5. 운영체제는 지금까지 개발된 가장 복잡한 소프트웨어 중 하나!

### <strong>Modern OS Functionality</strong>

1. Concurrency
   - 여러 프로세스가 동시에 활성화
   - 프로세스 간 의사소통 가능
   - 프로세스는 어떤 자원에 대해 서로 배타적인 접근을 필요로 할 수 있음.
   - CPU 스케쥴링, 리소스 관리
2. Memory management
   - 프로세스에 메모리 할당, 디스크와 메모리 간 프로세스 이동
3. File system
   - 디스크에 프로그램 및 데이터를 저장할 수 있는 공간 할당
4. Networks and distributed computing
   - 네트워크와 분산 컴퓨팅을 통해 컴퓨터들이 함께 작동 가능
5. Security & protection
   - 보안 및 보호

### <strong>History of Operating Systems</strong>

Phase 0 - 하드웨어 중심의 실험적 컴퓨팅 시대 (운영체제 없음)

1. 하드웨어는 너무 비쌈.
2. 운영체제가 없음. (사람이 직접 명령을 주고 기다림)
3. 한 명의 사용자만 컴퓨터 사용 가능.
4. 한 번에 하나의 작업만 실행.
5. 프로그램은 카드 덱으로 입력됨.
6. 디버깅은 콘솔에서 수작업.
7. 입출력을 위한 장치 드라이버는 라이브러리로 존재.

Phase 1 - 하드웨어는 비싸고, 사람은 싸다

- Simple Batch Processing
  1. 사용자는 프로그램(카드 or 테이프 형태)을 운영자에게 제출하고, 운영자는 작업들을 일정에 따라 정리하여 실행시킴.
  2. Resident monitor(상주 모니터)는 사용자 작업을 자동으로 불러오고, 실행하며, 결과를 덤프함.
  3. 이 과정에서 메모리 관리(재배치)와 보호가 필요함.
  4. 하드웨어를 더 효율적으로 사용할 수 있지만 결과가 덤프 형식으로만 제공되므로 디버깅은 어려워짐.
- CPU와 I/O 동작의 중첩
  1. First - 느린 I/O 장치의 데이터를 빠른 테이프 드라이브에 버퍼링하여 CPU에 연결하고, I/O 장치를 복제해서 동시에 더 많은 작업을 처리함.
  2. Later - 데이터를 디스크에 스풀링(spool)하여 처리 효율을 향상시킴. (spool -&gt; 느린 장치의 입출력을 임시로 디스크에 저장해두고, CPU가 놀지 않도록 하는 방식)
- 다중 프로그래밍 배치 시스템 (Multiprogrammed Batch Systems)
  1. 여러 개의 작업이 디스크에 저장된 상태로 실행을 기다리고 있음.
  2. Multiprogrammed(다중 프로그래밍): 여러 프로그램을 "동시에" 실행하는 것처럼 보이게 함.
  3. 작업 방식
     - 몇 개의 작업을 선택해서 실행 (스케줄링)
     - 메모리에 올림 (메모리 관리)
     - 하나의 작업이 입출력 대기에 들어가면, 즉시 다른 작업으로 전환해서 CPU가 쉬지 않게 함.
  4. 첫 번째 큰 실패 사례들
     - MULTICS: 1963년에 발표되었지만, 실제 출시까지 6년이 걸림.
     - IBM OS/360: 출시 당시 이미 1000개 이상의 알려진 버그가 있었음.
  5. 운영체제 설계는 예술이 아니라 과학이 되어야 한다. (체계적이고 과학적인 접근 필요)

Phase 2 - 하드웨어는 싸지고, 사람은 비싸졌다 (Interactive Time-Sharing)

- 대화형 시분할 시스템(Interactive Timesharing)
  1. 싸고 단순한 단말기(terminal)들이 많이 생기고, 하나의 컴퓨터에 여러 사용자가 동시에 접속해서 작업함.
  2. 디버깅이 쉬워짐 - 사용자와 실시간으로 상호작용 가능, 즉시 입력과 출력 확인 가능
- 디스크도 저렴해짐 -&gt; 프로그램/데이터를 온라인에 저장
  - 펀치카드 한 장 = 약 100바이트
  - 1MB = 약 10,000장
  - OS/360을 카드로 보관하면 수 미터 길이가 됨
- 새로운 문제들 등장
  1. 선점형 스케줄링 (preemptive scheduling) 필요
     - 반응 시간을 빠르게 유지하기 위해
     - CPU가 한 작업에 너무 오래 묶이지 않도록 강제로 전환
  2. 스래싱(thrashing) 방지 필요
     - 프로그램을 메모리 안팎으로 너무 자주 교체하면 성능 저하
     - 효율적인 메모리 관리 필요
  3. 보안 문제 대두
     - 여러 사용자가 동시에 시스템을 쓰기 때문에, 개인 데이터 보호와 접근 제어가 중요해짐
- 성공 사례: UNIX
  1. UNIX 운영체제는 벨 연구소에서 톰슨과 리치 두 사람이 개발
  2. 계기: PDP-7 미니컴퓨터가 놀고 있어서 스타트렉 게임을 만들고 싶었음

Phase 3 - 하드웨어는 매우 싸지고, 사람은 여전히 비쌈

- 개인용 컴퓨팅 (Personal Computing)
  1. CPU가 너무 저렵해져서 각 터미널(사용자 기기)에 하나씩 장착 가능해짐
     - 성능도 좋아서 유용하게 쓸 수 있음
     - "모두를 위한 컴퓨터" 시대!
  2. 운영체제는 다시 단순함으로 회귀함.
     - 멀티 프로그래밍, 동시성, 보호 기능 XXX -&gt; 당시 개인용 컴퓨터에선 굳이 필요하지 않았기 때문

현대의 운영체제

- 엄청나게 거대함
  1. 작은 OS: 약 10만 줄의 코드
  2. 큰 OS: 약 1천만 줄 이상
- 매우 복잡함
  1. 개발에 100~1000 인년이 걸릴 정도
- 완전히 이해하기 어려움
  1. 개발자가 은퇴하거나 사라져도 OS는 계속 존재함
  2. 너무 방대해서 한 사람이 전체를 이해하는 것이 불가능함

### <strong>More Recent Developments</strong>

1. 병렬 운영체제 (Parallel Operating Systems)
   - 공유 메모리(shared memory)와 공유 시계(shared clock)를 사용함
   - 서로 긴밀히 연결된 수많은 프로세서들로 구성
   - 사용자 입장에서는 하나의 운영체제처럼 보임
2. 분산 운영체제 (Distributed Operating Systems)
   - 공유 메모리 없음, 공유 시계 없음
   - 느슨하게 연결된 소수의 프로세서들로 구성
   - 목표는 사용자 입장에서 하나의 운영체제처럼 보이게 하는 것
   - 대신, 공유 메모리를 흉내 내는(simulate) 시도를 하기도 함
3. 실시간 운영체제 (Real-Time Operating Systems)
   - 실시간 제약 조건을 충족해야 함
     - 하드 실시간(hard real-time): 반드시 정해진 시간 안에 처리해야 함
     - 소프트 실시간(soft real-time): 정해진 시간 안에 처리하는 것이 이상적이지만, 약간 늦어져도 괜찮음.
